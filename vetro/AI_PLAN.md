# PhotoCraft by Vetro — как внедрять ИИ-функции

Отчёт-предложение (2026-10-13). Что делать, на каких моделях, где их запускать и как результат
попадает в документ. Цифры трудоёмкости — оценки, а не замеры.

## Коротко

1. **Не всё через OpenRouter.** OpenRouter — шлюз к большим моделям: языковым, «зрячим» (VLM,
   понимают картинку) и генераторам изображений. Он хорош для двух вещей: *понять сцену*
   (что на фото, где люди, где горизонт) и *сгенерировать новое содержимое* (заменить объект,
   дорисовать край кадра). Моделей, которые выдают точную маску по пикселям, удаляют царапины,
   восстанавливают лица или увеличивают разрешение (SAM, LaMa, GFPGAN, Real-ESRGAN), на
   OpenRouter нет: это небольшие специализированные сети, и их правильнее запускать **локально**.
2. **Гибрид из трёх слоёв:**
   - локально, ONNX Runtime на GPU — всё, где нужна точность до пикселя и мгновенный отклик;
   - OpenRouter — понимание сцены, генеративная замена, текстовые команды;
   - запасной облачный хостинг (Replicate или fal) — только если нужной модели нет локально и
     на OpenRouter.
3. **Результат ИИ — это обычные слои, маски и выделения.** Движок уже умеет всё нужное:
   выделение из маски, слой с маской, вставка картинки слоем, размытие по маске. ИИ только
   *предлагает пиксели и маски*, редактирование остаётся неразрушающим, а каждое действие —
   один шаг истории.
4. **Начать с того, что даёт эффект без генерации:** умное выделение с подсказками (люди, небо,
   вода, горизонт), удаление фона, сглаживание кожи, удаление объекта. Генеративную замену и
   восстановление старых фото делать вторым и третьим этапом.

## Что уже есть

В движке уже работают «умные» функции на классических алгоритмах, без нейросетей:

- Select Subject, Select Sky, Object Selection, Quick Selection, Select and Mask
  (`photocraft_algo::segment` и `matting`: GrabCut / max-flow);
- Remove Background (маска из Select Subject), инструмент Remove и Content-Aware Fill
  (достраивание по соседним фрагментам);
- фильтры, которые ИИ-функции могут использовать как «руки»: Surface Blur, Lens Blur с картой
  глубины, Camera Raw, кривые.

Нейросетевого рантайма в движке нет: это пробел G15 в `docs/gaps.md`, и решение по лицензиям
моделей и «локально или в облаке» отмечено там как решение владельца.

Отсюда вывод: ИИ не заменяет движок, а **поставляет ему маски и пиксели**. Классические
команды остаются запасным вариантом без сети и без GPU.

## Архитектура

```
VetroView (C++)                    панель «ИИ», подсказки на холсте, прогресс, отмена
   ↕ C ABI                         pc_ai_* — асинхронно, через очередь заданий (jobs)
crates/ai (Rust, новый)            модели, кэш, клиент OpenRouter, конвейеры функций
   ├─ local: ort (ONNX Runtime) + DirectML/WinML на той же видеокарте
   ├─ cloud: OpenRouter (VLM, генерация), запасной хостинг
   └─ результат → команды движка (маска → выделение, слой + маска, фильтр по маске)
PhotoCraft Engine                  без изменений; только новые команды ai.* при желании
```

- **Новый крейт `photocraft-ai`**, подключённый к мосту так же, как GPU-холст. Существующие
  крейты движка не трогаем, а AGENTS.md (никаких паник, слои зависимостей) соблюдаем. Если
  понадобится, результат оформляется командами `ai.*` в отдельном модуле — так AGENTS.md и
  велит добавлять функциональность.
- **Как результат попадает в документ.** Через то, что уже есть:
  - вставка PNG слоем: `file.placeEmbedded`;
  - маска в выделение: `select.loadSelection` из канала или слоя;
  - маска слоя, фильтр по выделению.
  
  Чище — дать мосту функцию «поставить маску в выделение» и «добавить слой из буфера» прямо
  по снимку документа, без временных файлов.
- **Локальный запуск.** Крейт [`ort`](https://onnxruntime.ai/) (ONNX Runtime).
  - На Windows работает через провайдер DirectML. Он в режиме поддержки; новые возможности
    Microsoft развивает в WinML с тем же API ONNX Runtime
    ([документация](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)).
  - Модели экспортируются с opset ≤ 20 (предел текущего DirectML).
  - Если нет GPU — тот же код на CPU.
- **Модели не кладутся в установщик.** Менеджер моделей скачивает их при первом
  использовании, проверяет SHA-256, хранит в `%LOCALAPPDATA%\PhotoCraft by Vetro\models`,
  показывает размер и лицензию.
- **OpenRouter.**
  - Распознавание сцены: чат-эндпоинт с картинкой на входе.
  - Генерация: модели с выводом изображений — `modalities: ["image","text"]` в чате или
    отдельный Image API `/api/v1/images` с опорными изображениями
    ([документация](https://openrouter.ai/docs/features/multimodal/image-generation)).
  - Каталог генераторов меняется (Gemini Image, GPT Image, FLUX, Seedream и др.), поэтому
    модель выбирается в настройках, а не зашивается в код.
  - Ключ API хранится в Диспетчере учётных данных Windows и никогда не попадает в
    репозиторий или логи.
- **Цвет и размеры.**
  - В облако уходит sRGB 8 бит; в локальные модели — в их собственном формате.
  - Большие фото режутся на тайлы или обрабатывается вырезка вокруг маски с полем контекста.
  - Результат возвращается в цветовое пространство документа через `photocraft-cms`.
- **Потоки.**
  - Всё идёт в фоне через уже существующую очередь заданий: интерфейс живёт, есть прогресс и
    отмена.
  - Тяжёлый энкодер (SAM) считается один раз при открытии фото и кэшируется по ревизии
    документа. После этого каждый щелчок даёт маску за десятки миллисекунд.
- **Приватность.**
  - Переключатель «Только локально» выключает все облачные функции.
  - Перед первой отправкой в облако — явное согласие и пояснение, что именно уходит (вырезка
    или всё фото).

## Функции

### 1. Умное выделение и подсказки («что на фото»)

**Для пользователя.**
- При открытии фото в фоне появляются чипы-подсказки: «Люди ×2 · Небо · Вода · Горизонт ·
  Здание».
- Наведение на чип подсвечивает область на холсте, щелчок делает выделение. Shift добавляет,
  Alt вычитает, как у остальных инструментов выделения.
- Инструмент Object Selection сам подсвечивает объект под курсором, и его можно выделить одним
  щелчком.

**Как устроено.**
- **Маски.** SAM 2.1 (Apache 2.0, есть готовые ONNX-экспорты энкодера и декодера, от tiny до
  large) ([HF](https://huggingface.co/vietanhdev/segment-anything-2.1-onnx-models)).
  - Энкодер считается один раз на фото.
  - Декодер по точке или рамке выдаёт маску мгновенно.
- **Что это за объекты.** Два варианта:
  - (а) локальный детектор сегментации (YOLO-seg, RT-DETR; проверить лицензию: часть моделей
    под AGPL) — классы «человек, небо, машина…»;
  - (б) VLM через OpenRouter: «перечисли объекты и дай рамки в JSON», а рамки уходят в SAM как
    подсказки.
  
  Вариант (б) понимает что угодно («кружка на столе»), но медленнее, платный и требует сети;
  вариант (а) мгновенный и офлайн. Рекомендация: (а) для базовых классов, (б) — по кнопке
  «Найти…» с текстовым запросом.
- **Небо и вода** — сегментация сцены (класс «небо» есть у большинства моделей) или уже
  существующий Select Sky, уточнённый маской SAM.
- **Горизонт** — граница маски неба или воды, аппроксимированная прямой (RANSAC). Действия:
  «Выровнять горизонт» (поворот плюс кадрирование) и «Выделить ниже/выше горизонта».

  2026-10-15, VT-85: ручное выравнивание реализовано командой `image.guidedUpright`. Одна горизонтальная линия задаёт поворот; пары сходящихся линий — перспективу. Будущий детектор горизонта может передать её в `lines` этой команды и затем вызвать кадрирование. Автоматический поиск горизонта и автоматическое кадрирование остаются задачами этого ИИ-плана.
- **Края** доводятся существующим Select and Mask (matting): волосы и мех получаются
  аккуратнее, чем у голой маски SAM.

**Оценка:** 2–3 недели (менеджер моделей и SAM — 1, детектор и подсказки — 1, горизонт и
интерфейс — 0,5–1).

### 2. Удаление фона и объектов

- **Удаление фона.**
  - BiRefNet (MIT) или аналог даёт маску переднего плана.
  - Результат — существующий Remove Background, но с нейросетевой маской.
  - RMBG-2.0 от BRIA качественный, но некоммерческий — не брать.
- **Удаление объекта** (щелчок или мазок по лишнему):
  - маска уточняется SAM;
  - достраивает LaMa (Apache 2.0) локально, вырезкой с контекстом;
  - результат — новый слой «ИИ: удаление» с маской.
  
  Классический Remove остаётся запасным вариантом. LaMa отлично убирает провода, прохожих и
  мусор, но не придумывает сложное содержимое — для этого генеративная замена.

**Оценка:** 1–1,5 недели.

### 3. Быстрая генеративная замена элемента

**Для пользователя.** Выделить (лассо, умное выделение или щелчок по объекту), написать
«красная машина» или «убрать и заполнить травой» и получить 2–4 варианта на выбор, как
Generative Fill.

**Как устроено.**
1. Вырезка вокруг выделения с полем контекста (например, +50% размера, итог до 1024–2048 px)
   плюс маска.
2. Запрос к генератору изображений на OpenRouter: изображение вырезки, маска (вторым
   изображением или как прозрачность) и промпт. Промпт строится так: «перерисуй только
   выделенную область: …, остальное сохрани», плюс авто-описание сцены от VLM для
   согласованного света.
3. Ответ масштабируется обратно, выравнивается по вырезке (генераторы иногда немного сдвигают
   и меняют весь кадр) и **вклеивается только внутри растушёванной маски**.
4. Цвет и шум подгоняются к окружению: перенос статистики по кольцу вокруг маски и добавление
   зерна под исходник.
5. Итог — смарт-слой «ИИ: …» с маской, варианты переключаются в панели свойств, как в
   Photoshop.

**Риски.**
- Разрешение генераторов ограничено: для крупных объектов на 24-Мп фото нужен upscale
  результата (п. 5).
- Генераторы перерисовывают весь кадр — поэтому вклеиваем только маску.
- Политики контента провайдеров: отказ нужно показывать понятно.
- Стоимость за запрос: показывать её до отправки, цены смотреть в живом каталоге.

**Расширение кадра (Generative Expand)** — то же самое, только маска — новая область холста
после Crop.

**Оценка:** 2–3 недели вместе с выравниванием и подгонкой цвета.

### 4. Сглаживание кожи (портретная ретушь)

Генерация не нужна, и так даже лучше: детали и личность сохраняются полностью.

1. Найти лица: YuNet (OpenCV, Apache 2.0), SCRFD или BlazeFace.
2. Разметить лицо: BiSeNet face-parsing (MIT) даёт маски кожи, бровей, глаз, губ и волос. Из
   маски кожи вычитаются глаза, брови, губы и ноздри.
3. Сглаживание:
   - частотное разложение: низкие частоты слегка размываются, текстура (высокие частоты)
     сохраняется с ползунком «Текстура»;
   - или существующий `filter.blur.surfaceBlur` по маске.
   
   Итог — отдельный слой «ИИ: кожа» с маской и ползунком силы.
4. Дополнительно:
   - прыщи и пятна — маленькие тёмные области на коже, удаляются LaMa или классическим
     Remove;
   - «убрать блики» — понижение яркости по маске кожи.

**Оценка:** 1–1,5 недели.

### 5. Восстановление старых фото и улучшение качества

Конвейер из шагов, каждый — отдельный слой, его можно выключить:

1. **Царапины и пыль.** Детектор царапин из «Bringing Old Photos Back to Life» (Microsoft, MIT)
   или простая модель-сегментатор, затем LaMa по маске.
2. **Шум и JPEG-артефакты** — небольшие модели шумоподавления (NAFNet, SCUNet; проверить
   лицензии) или классический фильтр.
3. **Лица** — GFPGAN (Apache 2.0). CodeFormer качественнее, но его лицензия (S-Lab) —
   некоммерческая: брать только если продукт некоммерческий. Сила восстановления — ползунком:
   смесь с оригиналом, чтобы не «подменить» человека.
4. **Колоризация** — DDColor или аналог (проверить лицензию) с ползунком насыщенности.
5. **Увеличение** — Real-ESRGAN (BSD-3) ×2 или ×4, тайлами, локально. Отдельно та же функция
   нужна как «Увеличить изображение (ИИ)».

Облачная альтернатива «отреставрируй фото» через генератор проще, но меняет лица и детали —
только как вариант «творческой» реставрации.

**Оценка:** 2–3 недели на весь конвейер (по отдельности — 2–4 дня на шаг).

### 6. Ещё функции, которые хорошо ложатся на архитектуру

- **Текстовые команды.**
  - «Сделай теплее и подними тени», «обрежь под 4:5», «размой фон».
  - Все действия движка — команды с описанием параметров. LLM через OpenRouter получает
    список команд и состояние документа и возвращает JSON-план из 1–5 команд.
  - Оболочка показывает план и применяет его одним шагом истории.
  - Это самая дешёвая из «вау»-функций: генерации пикселей нет, а движок уже готов.
- **Карта глубины → размытие фона** («портретный режим»). Depth Anything V2: малая модель под
  Apache 2.0, крупные — некоммерческие. Готовый `filter.blur.lensBlur` с картой глубины
  довершает дело.
- **Замена неба:** маска неба (п. 1) плюс сгенерированное или библиотечное небо плюс подгонка
  цвета переднего плана.
- **Авто-коррекция**: VLM смотрит на фото и предлагает настройки Camera Raw (экспозиция, баланс
  белого) — результат открывается в уже существующем диалоге Camera Raw, где их можно
  поправить.
- **Подписи и поиск по слоям**: VLM называет слои по содержимому («Слой 3» → «Кружка»).

## Интерфейс

- **Панель «ИИ»** — плавающий док в общем стиле Vetro:
  - подсказки выделения;
  - функции кнопками («Удалить фон», «Кожа», «Реставрация», «Увеличить»);
  - поле запроса для генерации и текстовых команд;
  - на каждой кнопке значок «локально» или «облако», для облачных — оценка стоимости.
- **Контекстно.** ПКМ по выделению — «Заменить (ИИ)…», «Удалить (ИИ)». Инструмент Object
  Selection подсвечивает объект под курсором.
- **Всё неразрушающее.**
  - Результат — слой «ИИ: …» с маской, одна запись в истории.
  - Варианты генерации переключаются в свойствах слоя.
- **Прогресс и отмена** — через существующую капсулу статуса и очередь заданий: пока сеть
  думает, интерфейс живёт.
- **Настройки:**
  - ключ OpenRouter;
  - выбор моделей (VLM, генератор);
  - «Только локально»;
  - папка и размер моделей, удаление скачанных.

строку в `ATTRIBUTION.md`, а файлы моделей в git не коммитятся.

## Этапы

| Этап | Что | Оценка |
|---|---|---|
| 0. Фундамент | крейт `photocraft-ai`, `ort` + DirectML/WinML, менеджер моделей, клиент OpenRouter, ключ в Credential Manager, `pc_ai_*` в мосту, панель «ИИ» | 1,5–2 недели |
| 1. Выделение | SAM 2.1, подсказки (люди, небо, вода, горизонт), удаление фона, выпрямление горизонта | 2–3 недели |
| 2. Ретушь | удаление объектов (LaMa), сглаживание кожи, прыщи | 2 недели |
| 3. Генерация | замена элемента, расширение кадра, варианты, подгонка цвета | 2–3 недели |
| 4. Реставрация | царапины, шум, лица, колоризация, увеличение | 2–3 недели |
| 5. Язык | текстовые команды (LLM → команды движка), авто-коррекция, имена слоёв | 1–2 недели |

Итого примерно 3–3,5 месяца одного разработчика до полного набора. Первый заметный результат
(этапы 0–1) — через 3–5 недель.

## Что решить до начала

1. **Продукт коммерческий или нет?** От этого зависит набор моделей (CodeFormer, RMBG, часть
   Depth Anything).
2. **Облако по умолчанию или только по явному согласию?** Рекомендация: локальное — всегда,
   облачное — по кнопке и с согласием.
