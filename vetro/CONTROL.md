# Управление запущенным Vetro

Канал управляет тем же документом и тем же движком, что окно Vetro. По умолчанию он выключен: в «Настройки → Интеграции» порт равен 0. Для включения разрешите управление агентам и задайте свободный порт, например 7878. Изменения применяются по OK; выключение закрывает соединения.

Для отдельного запуска можно задать порт и файл токена явно:

```powershell
.\vetro\dist\PhotoCraftVetro.exe --control 7878 --control-token-file C:\work\vetro-control.token
.\vetro\dist\photocraft-cli.exe mcp --bridge 127.0.0.1:7878 --control-token-file C:\work\vetro-control.token
```

Второй процесс — существующий MCP-сервер PhotoCraft; он подключается к Vetro и не создаёт отдельный документ. Каталог инструментов MCP остаётся общим. При настройке клиента MCP укажите эту команду и аргументы как stdio-сервер. После первого запуска файл токена уже существует; не помещайте его содержимое в конфигурацию, журнал или Git. Без явного пути Vetro хранит токен в `%LOCALAPPDATA%\PhotoCraft by Vetro\control.token`. Состояние соединения видно в разделе «Интеграции». `--control 0` выбирает свободный порт, его номер также виден там. Разрешение «Управление агентам» действует и при запуске с флагом.

Транспорт совместим с [общим протоколом](../docs/control-protocol.md): TCP только на 127.0.0.1, JSON по строкам, первая строка — `auth`, ответы `{id, ok, result}` или `{id, ok:false, error}`. Авторизация, пределы сообщений и проверка доступных агенту команд взяты из `photocraft-automation`. Транспорт вынесен в приложение `apps/vetro-control` (L7); мост остаётся L6. Запросы, не начавшиеся за 60 секунд, отменяются. После начала долгой операции ответ об истечении срока прямо говорит, что операция могла завершиться.

Реализованы:

- `engine.commands`, `engine.execute {command, params}` — команды текущего движка, с общей проверкой доступа.
- `ui.inspect` / `app.state`, `app.documents`, `app.activateDocument {document}` — состояние окна и открытых документов.
- `ui.menu.list`, `ui.menu.invoke {id}` — реальные меню оболочки, включая рабочие среды и диалоги.
- `ui.set {tool?, zoom?}` — инструмент и коэффициент масштаба (1 = 100 %). `ui.set {control, value}` меняет поле из последнего `ui.inspect.controls`: число, текст, переключатель или индекс списка. После изменения получите новый снимок: идентификаторы полей действуют до следующего `ui.inspect` и замены виджета.
- `ui.key {key, modifiers?:{ctrl?, command?, shift?, alt?}}` / `{text}` и `ui.pointer {events:[{kind:down|move|up, x, y, pressure?}], modifiers?, button?:left|right|middle}` — те же обработчики, что мышь и клавиатура. Пакет указателя задаётся в координатах документа, до 256 событий. Для одиночного события есть форма `{type, x, y, space?:document, ctrl?, shift?, alt?}`; без `space` координаты — DIP окна.
- `ui.screenshot {maxSide?:1280}` — PNG окна в поле `png` (base64), максимум 2048 по длинной стороне и 5 МиБ PNG.

По умолчанию файловых разрешений нет: `app.open` / `app.save` получают отказ. Для работы с файлами запустите Vetro с `--automation-read-root C:\work\images` и/или `--automation-write-root C:\work\output`. Каталоги должны существовать. Тогда `app.open {path}` и `app.save {path, copy?:false}` работают внутри соответствующего каталога, включая PNG, PSD и `.pcraft`. Чтение и атомарная запись идут через `AuthorizedWorkspace` с дескрипторами каталогов; обход через `..`, абсолютный чужой путь или ссылку за пределы каталога запрещён. Мост принимает/отдаёт байты и не открывает путь повторно. Без таких флагов используйте штатные диалоги Vetro. `engine.execute` с путями остаётся ограничен общим проверяющим кодом.

Для изолированных проверок есть `--hidden` и `--preferences-file <путь>`: они позволяют запускать отдельное скрытое окно со своим файлом настроек.

Нативный канал выполняет `engine.execute` с `wait:true`; перед прямой командой движка завершите или отмените активную рабочую среду. Неизвестные поля `ui.set` и неподдерживаемые методы возвращают ошибку. Вложенные шаги Actions и предпросмотры проверяются тем же ограничителем; обычные действия пользователя сохраняют свой доступ. Экспорт в плоский формат сохраняется копией и не меняет имя/путь исходного документа. Параметр `tgaBits` требует headless-экспорта.
