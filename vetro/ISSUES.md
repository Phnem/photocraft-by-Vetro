# Issues оригинального PhotoCraft и их релевантность для PhotoCraft by Vetro

Проверка 2026-10-14. Источник — PDF «Полная сводка и классификация Issues» (storytold/photocraft);
статусы сверены с GitHub в тот же день. Форк содержит оригинальный движок, синхронизированный с
`main` на 2026-10-13 (merge `ff3d8ffa`), и **собственную оболочку** (`vetro/shell`, C++ / Direct3D 11 /
Direct2D). Поэтому issue релевантна форку, только если

1. дефект живёт в движке или в общем коде (`crates/*`), который форк использует, либо
2. у оболочки Vetro есть своё поведение, где происходит то же самое.

Каждый вердикт подтверждён одним из способов: **пробой** (`vetro/shell/tests/issue_probe.cpp`,
`VetroIssueProbe.exe` печатает `REPRODUCED` / `not reproduced`), **живым запуском** приложения,
**чтением кода** (с `файл:строка`), **проверкой дерева** (`git log`, поиск в движке).
Релевантные issues вынесены в [Веху 9](TICKETS.md#веха-9-проверенные-issues-оригинала-и-дефекты-вех-45).

## После исправлений VT-70…VT-75 (2026-10-14)

Исторические воспроизведения ниже относятся к сборке milestone5. В сборке
`vetro/dist/milestone7` исправлены #5522, текстовые сценарии #5527/#5511 и зависимые
поля #4775, а также V1/V2/V8/V10 из проверки Вех 4–5. `milestone9` в ctest теперь
проверяет эти сценарии с отказом при регрессии. `VetroIssueProbe` проверяет V10 по
реальным строкам панели: пустое поле группы в данных набора само по себе допустимо.

#5526 / VT-69 (потеря клавиш при занятом движке) остаётся открытым. Остальные issues
этой итерацией не закрываются; изменения движка для VT-82 не выполнялись.
