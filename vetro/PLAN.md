# PhotoCraft by Vetro — план работ

Форк PhotoCraft с новой оболочкой. Движок (`crates/*`) не трогаем: новая оболочка общается с ним
только через C ABI, как на схеме:

Исключение по прямому запросу пользователя 2026-10-14: заполнение новых краёв при
кадрировании добавлено отдельной командой движка `image.cropContentAware`.

```
VetroView — C++          (vetro/shell)    всё взаимодействие · доки · анимации · glass
      ↑↓ C ABI           (crates/bridge)  photocraft_bridge.dll, заголовок vetro/shell/src/bridge.h
PhotoCraft Engine — Rust (crates/*)       слои · кисти · PSD · фильтры · история
      ↓
GPU: Direct3D 11 + Direct2D + DirectComposition (оболочка), CPU-композитор движка (холст)
```

Источники стиля и поведения (только чтение, ничего не меняем):

- `Vetro_Look/design.md`, `VetroView/docs/TOKYO_GLASS.md` — материал, радиусы, типографика, палитра;
- `VetroView/src/gfx.cpp`, `ui.h`, `theme.cpp` — D3D11→D2D→DComp, рецепт стекла, пружины;
- `Vetro-collection/.../TtmMenu.kt`, `StagedSheetMotion.kt` — морф меню из гнезда дока
  (путь DIRECT, пружина T=0.40 с ζ=0.78, закрытие ζ=1 k=900, каскад строк);
- `index.html` — концепт раскладки, `photocraft_ui_inventory.html` — иерархия инструментов и меню.

| VT-14 | Редакторы | Кривые с точками, Camera Raw (вкладки), Liquify (инструменты на холсте), Стиль слоя (список эффектов); поле цвета в генерируемых диалогах |

Вторая волна выполнена (2026-10-13). Проверено вживую на том же фото 3840×2400:

- холст идёт через GPU (в строке состояния «GPU»); таблица цвета Direct2D проверена тестовой таблицей
  (`VETRO_LUT_TEST=1`: порядок каналов RGBA, у Direct2D быстрее всего меняется синий — таблица
  движка транспонируется), Monitor Profile = Display P3 меняет пиксели холста как положено;
- Camera Raw (Basic, HSL), Кривые с точками (корректирующий слой), Free Transform (масштаб и поворот,
  превью движком), стиль слоя (Drop Shadow), перо → выделение, Штамп (Alt-щелчок, Aligned), Liquify
  (Forward Warp) — каждое действие одна запись в History, превью за собой не оставляет шагов;
- File › Save As через системный диалог: PNG 3840×2400 совпадает с холстом;
- интерфейс отзывчив, пока движок считает (очередь заданий, индикатор в капсуле статуса).

Мост: 9 тестов, clippy `-D warnings`, `cargo xtask layers`. `VETRO_CPU_CANVAS=1` включает прежний
CPU-холст.

## Принципы реализации

- Ни один элемент не рисуется «вручную по месту»: каждая кнопка, слайдер, список и меню — экземпляр
  класса из `vetro/shell/src/widgets.*`. Новые диалоги описываются данными (`dialogs.cpp`), а не кодом.
- Все видимые значения идут через пружины (`Spring`), ничего не телепортируется; Reduce Motion
  схлопывает пружины.
- Стекло везде одно: `GlassSurface` (одна функция, один рецепт).
- Иконки только Phosphor Regular (MIT), недостающие дорисованы в той же 256-сетке.

## Что осталось за рамками

- Документы больше 16384 px по стороне или 120 Мп и то, что GPU-композитор движка пока не берёт,
  показываются CPU-путём (переключение автоматическое).
- Пока движок занят, ввод в документ ждёт (появляется уведомление), но вид, доки и открытый диалог живут.
- Маска заморозки Liquify показывается по штрихам оболочки (без учёта нажима).
